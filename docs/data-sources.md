# Джерела даних і обробка словників

## Каталоги

```text
dictionaries/     незмінні знімки джерел + ліцензії + manifest.json (SHA-256 кожного файлу)
data/filters/     власні списки проєкту: контентний фільтр і доповнювальні слова
data/derived/     очищені словники, n-грами, звіт обробки (build-report.json)
data/texts/       власні речення й абзаци
data/curriculum/  уроки й модулі Академії
```

Файли в `dictionaries/` не редагуються. Їхні контрольні суми перевіряє `npm run verify:checksums`;
для наборів із пакета організатора суми збігаються з його `dictionaries/CHECKSUMS.sha256`.

## Алгоритм обробки (`scripts/build-data.mjs`, версія 1.0.0)

байти; це перевіряє тест `tests/data.test.mjs`, порівнюючи щойно зібрані файли із закоміченими.

### Крок 1а: російські слова в українському списку

Український список FrequencyWords зібрано із субтитрів, значна частина яких насправді російська:
слово «что» стоїть у ньому на восьмому місці. Hunspell відсіює більшість таких слів, але не омографи,
які формально є і в українському словнику («ладно», «конечно», «потом», «его»).

Метод:

1. Слова з літерами `ы э ъ ё` не можуть бути українськими. Відношення суми їхніх частот в
   «українському» списку до суми в російському дає коефіцієнт `k = 0,013982`: стільки вживань в
   українському списку припадає на одне вживання в російському.
2. Для кожного слова `k · f_ru` — очікувана кількість «російських» вживань.
3. Якщо вона пояснює понад 75 % частоти слова, слово вилучається. Для справді спільних слів
   («не», «на», «там») ця частка становить 30–55 %, для російських омографів — 85–115 %.
4. Частота решти слів зменшується на очікувану російську частку.

### Перевірка написання

`scripts/lib/hunspell.mjs` — власна мінімальна реалізація перевірки за `.dic` + `.aff`: точний збіг
основи, однорівневі суфікси, префікси та їх перехресне поєднання. Тест перевіряє її на відомих
прикладах (`книжками`, `найкращий`, `м'яч`, `walked`, `cities`; відхиляються `что`, `london`, `asdf`).

### Нормалізація

- Unicode NFC; словникові слова — у нижньому регістрі.
- Апостроф: `’` (U+2019), `ʼ` (U+02BC), `‘` (U+2018), `` ` `` (U+0060) → `'` (U+0027). Те саме правило
  діє для набраного символу, тому будь-який варіант апострофа зараховується.
- Літери `і ї є ґ` не замінюються ніколи: «г» замість «ґ» чи латинська «i» замість «і» — помилка
  набору (тести `tests/engine.test.mjs`, наскрізний тест української мови).

### Доповнювальні списки

У частотному списку апостроф утрачено під час токенізації («п'ять» розбито на частини), а слів із `ґ`
майже немає. Тому `data/filters/supplement-uk.txt` містить власний перелік таких слів, а
`supplement-en.txt` — англійські скорочення (`don't`, `it's`). Кожне слово під час збирання
перевіряється за Hunspell; слово, якого немає в словнику, зупиняє збирання. Частота цих слів
невідома, тому вони зберігаються окремим полем `supplement` і не впливають на частотність та n-грами.

### Контентний фільтр

`data/filters/blocklist-*.txt` — власні списки: лайка, теми, недоречні в навчальному тренажері,
уламки слів, звуконаслідування, власні назви в нижньому регістрі. Запис `основа*` відсікає всі слова
з таким початком.

## Формат похідних даних

`data/derived/<мова>/words.json`:

```json
{ "schema": 1, "language": "uk", "algorithmVersion": "1.0.0", "license": "GPL-3.0-or-later",
  "sources": ["dictionaries/uk/frequencywords-2018/uk_50k.txt", "…"],
  "words": [["я", 97723], ["не", 83316]], "supplement": ["п'ять", "ґанок"] }
```

Слова зберігаються компактно як `[слово, частота]`. Решту полів схеми ТЗ §5.3 (`characters`,
`bigrams`, `difficulty.sameFingerTransitions`, `difficulty.rowChanges`, `flags`) однозначно
відтворює функція `describeWord` у `src/core/word-info.js` — це перевіряє тест.

`data/derived/<мова>/ngrams.json` — біграми, триграми, закінчення, початки слів і подвоєння з вагою,
часткою та прикладами слів.

**Вага n-грами дорівнює сумі частот слів, у яких вона трапляється** (тест перераховує вагу
незалежно). Це частотність усередині слів; переходи між словами не оцінюються.

`data/derived/build-report.json` — контрольні суми входів і виходів та кількість записів після
кожного кроку. Сторінка «Джерела та ліцензії» у продукті показує цей звіт.

## Навчальна програма (`scripts/build-curriculum.mjs`)

Вхід: `data/derived/` і `data/texts/`. Вихід: `data/curriculum/{en,uk}.json`. Варіанти вправ
добирає генератор із фіксованим зерном (ідентифікатор вправи), тому файли відтворюються побайтно.
Типові морфеми задано переліком у скрипті, а їхня вага й приклади обчислюються зі словника.

## Власні тексти

Речення, абзаци та приклади з розділовими знаками й числами в `data/texts/` написано спеціально для
цього тренажера (складено AI-асистентом за завданням учасника). Вони не скопійовані з книжок, сайтів чи
диктантів.

## Як додати нове джерело

1. Покласти файл і його ліцензію в окремий каталог `dictionaries/<мова>/<набір>/`.
2. Додати запис у `dictionaries/manifest.json`: джерело, ревізія, ліцензія, файли.
3. Виконати `node scripts/checksums.mjs --write`, щоб записати суми.
4. Виконати `npm run build:data` і `npm run check`.
